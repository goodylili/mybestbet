# ingest

- Per-source request ceiling is `sources.<name>.maxRps`. Each price fetch counts the HTTP requests made under its context (discovery is not counted) and updates a moving average of requests per event (`ingest_requests_per_event{source}`; 1xBet-family sub-games make it several). Tier demand is weighed by that cost. Hot may use at most 60% of the ceiling; beyond that its interval stretches (at 8 rps, 15 hot events costing 3 requests each poll about every 9s). When the remaining demand exceeds the ceiling, the cold interval stretches first, then warm, capped at 30m.
- Discovery links every event with a future kickoff, however far out; only polling is bound to the tiers (config `tiers:` hot 2h@5s, near 6h@10s, warm 24h@30s, cold 7d@3m, far 90d@15m). Polling runs in two lanes that share the source's rate limiter. The hot lane fetches due hot events in batches of 4, so each batch is published within a couple of seconds. The cool lane fetches one batch of 8 cooler events at a time, most overdue first, measured as time past due divided by the tier interval. Never-polled events count as infinitely overdue, warmest tier first, so every newly discovered event is priced once before any repeat. A backlog of far events never waits behind the hot tier, and the reverse holds too. Each discovery logs `discovery linked` (discovered, upcoming, linked, latest kickoff, unlinked per league) and sets `ingest_discovered_events{source,state}`.
- Events users have open are polled as hot regardless of kickoff distance. The api keeps them in the sorted set `ingest:priority:events` (score = expiry in unix ms); ingest reads the unexpired members every 2s (`ingest_focused_events`), maps them to source events via the resolver's event links, and pulls their next poll to within one hot interval.
- Fetch timeout per tier is the tier interval clamped to 5s..20s; discovery gets 3s per requested league (72 leagues: 3m36s), at least 2m and at most the discovery interval.
- Unchanged markets are skipped by an xxhash of selections (sides, labels, prices, suspension, book fields, rules), excluding `ObservedAt`. Hashes commit only after the deltas are on `odds.delta` or buffered for review. A complete poll (no fetch errors) forgets the hashes of markets it no longer returned, so a market that comes back is sent again.
- Throttled (429) and forbidden (401/403) errors pause the source with exponential backoff (5s doubling, 5m cap). Three consecutive failures of any kind mark it degraded.
- Push sources stream every scheduled event. While the stream is live, REST reconciles every 5m; when it drops, every event is polled immediately and the tiers resume until reconnect. Each (re)connect resyncs from REST.
- Every poll re-confirms what it saw. The resolver XADDs one `canon.Freshness{Source, EventID, ObservedAt, SourceKeys, Complete}` per (source, canonical event) to `odds.delta` under field `f`, listing the source market ids returned for the event. `Complete` is set only for REST price polls without errors; stream messages are partial and never set it. The engine refreshes `observedAt` only for the listed markets, and on a complete poll it suspends the source's markets that were not listed.
- A `Stream` error exposing `PollsInstead() bool` (Kalshi/predict.fun without an API key) ends the stream loop quietly; the source keeps polling on its tiers.
