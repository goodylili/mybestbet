# pricing

Pure functions: implied probability conversion (`canon.ImpliedProb` and its inverse `RawFromProb`), de-vig, consensus fair price, bucket ladders, derived double chance / draw no bet, push-aware two-way payouts.

- **De-vig**: `power` solves `Σ q_i^k = 1` by bisection on k in [0.5, 3]; if no root lies in that bracket it falls back to multiplicative. The result is always renormalised so it sums to exactly 1. Method per market code comes from `pricing.devigMethod`, default `pricing.defaultDevig`. Double chance outcomes overlap, so DC is de-vigged multiplicatively to a total of 2.
- **OU uses power**: against liquid Polymarket mids (80 OU markets, 3+ book feeds, ≥$200 at the touch) the consensus fair error was 0.0067 with power vs 0.0172 multiplicative, and 0.0078 vs 0.0241 on outcomes under 20%. Books cap favourites near 1.001, so the margin belongs on the longshot, which is what power does. Cross-book dispersion is higher under power but is not a measure of accuracy.
- **Overround gate**: a source-market whose priced implied probabilities sum above `fairSum·(1 + pricing.maxOverround)` (fairSum is 2 for DC, else 1) is left out of consensus, arbs and +EV. It is still written to the board.
- **Consensus**: weighted median of each feed's de-vigged probability. Brands sharing one odds feed (`sources.<name>.feed`, default the source name: onexbet/22bet/paripesa/betwinner are `onexbet`, sportybet/footballcom are `sporty`) cast one vote with their mean probability and heaviest weight. Weight is `sources.<name>.weight` (default 1). Polymarket and Kalshi get `pricing.deepBookWeight` when touch liquidity is over `pricing.deepBookLiquidity`, otherwise 1. Fewer than `pricing.minFairSources` distinct feeds gives no fair price. An exact 50% weight split averages the two middle values.
- **Ladders**: bucket labels accepted: `<24`, `under 24`, `24-31`, `32+`, `32 or more`, `>=32`, `3 or fewer`, `<=3`. Buckets must partition 0..∞ with no gaps. Each inner edge e becomes a line at e-0.5 with `P(over) = Σ buckets ≥ e`. Implied (cost) and fair are summed separately, and touch liquidity is the thinnest bucket on that side.
- **Derived**: DC = sum of the two outcomes; DNB home = `p_home / (1 - p_draw)`. Applied to implied probabilities this is exactly the price of the synthetic hedge (back home, cover the draw so it returns the total stake), and applied to fair probabilities it is `p_home / (p_home + p_away)`.
- **Market shapes** (every sport): `FitsShape` checks a selection's side against `canon.SpecOf(code).Shape`: three-way home/draw/away, two-way (ML, QUALIFY, DNB) and handicap (AH, SPREAD, SET_HCP, MAP_HCP) home/away, totals and O/U props over/under, yes/no props yes/no, labeled and bucket markets anything. Unknown codes pass. `SettlesAgainstLine` is true for handicap and over/under shapes (AH, OU, CORN_OU, SPREAD, TOTAL, SET_HCP, TOTAL_GAMES, MAP_HCP, TOTAL_MAPS, every O/U prop) and for team-stat ladder rungs; only those take the push-aware arb path. De-vig is the same for every sport: a two-way ML is de-vigged like any two-outcome market, per-code `pricing.devigMethod` still applies, default `power`.
- **Derived markets are football only**: DC/DNB come from the full-time `1X2`, which only football has. ML and QUALIFY are never used to derive anything.
- **Push-aware payouts**: AH line is the home handicap (home result = goal difference + line); totals use goals - line for over. Quarter lines split the stake across line ± 0.25. `WorstPushAwareReturn` checks every integer score around the line and skips the scenario where every stake is refunded, because a full refund is not a loss. The same integer-result grid serves points (basketball/NFL), games (tennis), maps (esports) and prop stats. It also contains results a format cannot produce (a set difference of 0 in a best-of-three), which can only lower the worst case, so it never reports an arb that is not there.
