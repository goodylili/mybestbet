# resolve

- Team match: exact alias, then normalized Jaro-Winkler (boost 0.7, prefix 4) within the league, also scoring 0.95 when one name's tokens are a subset of the other's. Auto-link at >= 0.93 only when the runner-up trails by more than 0.02.
- Fixture opponent: when exactly one side of a source event settles (exact alias or auto-link) and the anchor has exactly one fixture in the league within the kickoff tolerance, the other side is that fixture's opponent provided its name scores >= 0.60 and no other league team scores >= 0.93 and above it by more than the margin. Nothing is persisted for the inferred name (only the event link), so a nickname never becomes an alias. Off in `collegeLeagues`.
- Women-only competitions (every member team carries the women qualifier, e.g. UWCL) imply the qualifier on source names without one ("Arsenal WFC", "Chelsea").
- `resolve.collegeLeagues` (NCAAF, NCAAB): a one-token name never counts as a token subset ("Utah" is not "Utah State Aggies"). In every league a subset never adds `state` ("Arkansas" vs "Arkansas State").
- Player match: exact alias, unique full name (any order), unique surname + first initial (either order, so Arabic and surname-first names work; when both given names are spelled out they must agree, so "Raul Garcia" never takes "Ruben Garcia"), unique containment of the shorter name in the longer one ("Nilson David Angulo Ramirez" -> "Nilson Angulo"), then Jaro-Winkler >= 0.90 with the same ambiguity margin. Name tokens agree when equal, one is a prefix (>= 3 letters) of the other, or Jaro-Winkler >= 0.88. A fuzzy score only counts when the names share a surname and a given name; otherwise it is capped at 0.85 so "Souleymane Toure" cannot land on "Souleymane Faye".
- One source player per canonical player per source: a match already claimed by another source key of the same source goes to review (two different Al Dossaris on one book), unless one name is a token subset of the other (Bayse "Haaland" next to "Erling Haaland"). On load, contested aliases keep only the single exact (confidence 1) claim; if there is none or several, all are dropped and re-resolved. A fresh auto-link replaces a stored fuzzy alias (confidence < 1) but never an exact or reviewed one (confidence 1); the matcher is deterministic, so replays are no-ops. Sportradar books name one id differently per market ("Souleymane Toure" on scorer markets, "Isaak Toure" on 800xxx props), which is how a weak early link gets corrected.
- `ResolveAndPublish` also takes the polled source events (`PolledEvent{SourceEventID, SourceKeys, Complete}`) and XADDs one `canon.Freshness` per linked canonical event (field `f`) after the deltas. XADDs go out in pipelines of 500 so that a large first poll (a SportyBet event carries about 1,250 markets) cannot hit the Redis read timeout. A failed chunk returns `ErrNotDelivered`, and ingest re-sends the whole poll; replays are idempotent. Source events linked to the same canonical event merge their keys, and the result is complete only if all of them were.
- Teams belong to many competitions (`team_leagues`, migration 0017); the pool for a league is every member's name and aliases. An exact alias only counts when its team is a member of the event's league, so a book alias for Portugal's "Nacional" never lands a Libertadores event on it. When the stored alias already points elsewhere, the fuzzy result is used without persisting.
- Each candidate is scored on the synonym-mapped name and on the literal name, so a global synonym ("Spurs" -> Tottenham) cannot hide "San Antonio Spurs" in the NBA pool. Squad qualifiers (women/W, B, II, U21, academy, youth, Castilla, Jong ...) must agree on both sides or the score is 0.
- Tennis: competitors are matched with the person matcher across every tennis league ("Sinner J." in ATP_MIAMI finds the ATP_AO row) and join the event's league on link. An unmatched full name (2+ tokens, no initials, best candidate < 0.80, not a doubles pair) creates the competitor (team + player + alias), so Challenger draws resolve without seeding.
- Esports players: exact handle only (case and punctuation folded, quoted nickname extracted from "Mathieu 'ZywOo' Herbaut"); anything else goes to review.
- US sports: generational suffixes (Jr., II, III, IV) are dropped from 3+ token names; a trailing "St." in team names means State ("Michigan St."), a leading one Saint.
- Kickoff tolerance comes from the `resolve:` block of config.yaml (`kickoffTolerance` 15m, `sportKickoffTolerance.tennis` 12h because order-of-play matches "follow" earlier ones and books only list the session start). The same values drive seed event adoption.
- Labelled sets in `testdata/` cover all five sports (teams: 10 football leagues + UCL/UWCL/FRIENDLY, NBA, NCAAB, EuroLeague, NFL, ATP, CS2, LoL; players: football, NBA, NFL, tennis, CS2). Precision is 1.00 for teams and players in every sport (targets 0.98 / 0.95).
- Redis keys not yet in `internal/platform/redis`: `resolve:pending:<kind>:<source>:<sourceKey>` (hash of buffered raw markets, 6h TTL), `resolve:pending:index` (set of buckets), `resolve:held:<source>` (unlinked source events), `resolve:held:sources`.
